# LES：前瞻专家调度

[English](lookahead-expert-scheduling.md) | 中文

LES 把 **MiniCPM-V 4.7 35B-A3B** 的路由专家放到闪存上按需读取，并把读盘隐藏在本就在进行的
GPU 计算之后。读 1 个专家（约 1.00 ms）和算 1 整层（约 1.15 ms）耗时相当，所以按需读盘会让
磁盘延迟决定节奏，而 GPU 只能空等。

下面四项打破了这种串行依赖，结果见文末示意图。

## 亮点

- **前瞻专家。** 第 L 层的隐状态已经很接近第 L+1 层路由将要看到的那个，把它乘上第 L+1 层的路由
  权重，就能提前一层预测出该层的 top-k。预测出的专家在第 L 层计算期间从 SSD 取回，与第 L+1 层
  的注意力并行而不是阻塞它，约 81% 在轮到它那一层时已在槽位里。无需训练，且无损：真正决定跑
  哪些专家的仍是路由算出的 top-k。

- **调度优化。** 围绕前瞻这一思路重整引擎，让读盘不再压在关键路径上：专家权重重排成更少、更大的
  读取；读到的数据直接写进 GPU 可见内存，不经中间拷贝；绕开页缓存，避免它重复占用专家窗口已有的
  数据；常驻专家窗口加宽并按层取形；常用专家在 prefill 之前预热，让首 token 不是纯读盘时间。

- **精细化量化。** 不做统一量化，而是用参数搜索在各张量组之间分配精度：占读取字节大头的部分压得
  更狠，影响精度的部分保留精度。

- **DSpark。** 一个投机解码阶段，与 LES 在同一 decode 路径上叠加。
